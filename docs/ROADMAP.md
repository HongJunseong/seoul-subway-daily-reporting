# 고도화 로드맵

작업은 의존성과 완료 증거를 기준으로 진행한다. 테스트 수나 기술 수를 성과로 대체하지 않는다.

## Phase 1 — 데이터 정확성
- [x] 명시적 Bronze 스키마·원문·수집 lineage
- [x] 승하차 페이지별 건수·수집 내부 자연키 검증과 반복 페이지의 Bronze append 차단
- [x] 승하차 재수집 중복 제거·최신 정정 반영
- [x] Delta 루트 읽기와 날짜 단위 교체
- [x] 15분 집계의 시간·날짜 경계 수정
- [x] NULL ETA 보존·유효 표본 분모 분리
- [x] 환승역 역명 조인 제거·가중 평균·분위수 의미 정리
- 완료 증거: Spark/Delta 회귀 테스트, fixture 정정·재처리 실험

## Phase 2 — 자동화·복구
- [x] 수집 DAG와 원본 처리 DAG 분리
- [x] 일간 자동 수집에서 Gold·보고서로 연결
- [x] 공통 실행 구간과 수동 날짜 검증
- [x] 원본 재처리 CLI·API 재수집 opt-in
- [x] S3 writer 공유 pool 직렬화·수동 실행 제약 문서
- [x] Kafka 제거·알림 실패와 보고서 실행 분리
- 완료 증거: 실제 Airflow DagBag·템플릿·의존성 검사

## Phase 3 — 재현 가능한 결과
- [x] 키 없는 합성 데이터 end-to-end 데모
- [x] 결정적 보고서·입력 context·publication hash
- [x] 의미 있는 회귀 테스트와 CI 정의
- [x] 로컬 Delta 품질·시간 구간·처리 누락·파일 감사 CLI
- [x] 실제 Delta 커밋 후 예외 주입·품질 실패·원본 재처리 복구 실험
- [x] Airflow lifecycle 로그와 시도별 실행·executor 대기 집계
- [x] 저장된 합성 Bronze에서 실제 Airflow 태스크·XCom·DAG 트리거·보고서 연결 실행
- [x] 소량 실제 서울 API 관측·응답 상한 경고·로컬 원본 재처리 일치의 공개 증거
- [x] 저장된 여러 날짜의 캡처 비교 도구: 실패·일정 놓침·기록 누락·미확인 날짜와 분모 구분
- [ ] 실제 수집 데이터의 장기 결측·건수·커버리지 baseline 수립
- [ ] 배포 환경에서 수집 신선도·실행 시간·복구 시간 측정
- Phase 3의 실운영 항목은 live 서비스 검증 증거가 있어야 완료한다.

## Phase 4 — 포트폴리오 평가 근거
- [x] 문제→설계→오류 개선→검증→결과의 README
- [x] 데이터 계약·ADR·복구 runbook·검증 제한 문서
- [ ] 샘플 외 실제 데이터 관측 결과와 운영 기간 기록
- [x] 더 큰 합성 입력의 파일 수·조회 시간 측정과 닫힌 시간 compaction의 결과 보존 검증
- [ ] 실수집 장기 파일 분포·S3 읽기/쓰기 비용으로 유지보수 주기·파티션 변경 판단
- [ ] 보존 기간·API 페이지 상한·운영 시간대 정책을 실측으로 확정

## 작업 선택
미완료 live 항목을 문서·합성 결과로 완료 처리하지 않는다. 외부 접근이 없으면 독립적인 코드·재현·검증 작업을 진행한다.
새 기능이 검증 목표를 늘리지 않으면 추가하지 않는다.

## Phase 5 — 플랫폼과 실행 증거
- [x] 공통 승하차 변환의 Databricks managed Delta adapter
- [x] ANSI 불량 수치·날짜 차단, 날짜별 MERGE와 인접 날짜 보존
- [x] 기존 Free Edition serverless Job 네 태스크 실제 성공과 재처리 해시 비교
- [x] KubernetesExecutor 자원 프로필, 고정 chart/provider, namespace RBAC, lake/log PVC 설정
- [x] 공식 Helm 렌더·실제 Airflow 태스크 17개 Pod 병합과 직렬화 검사
- [x] 실제 Kubernetes scheduler→worker Pod→보고서 실행 및 PVC binding
- [x] worker 실패 후 다른 Pod 재시도, 삭제된 Pod의 로그 보존 확인
- [x] 동일 Bronze의 실제 Pod 재처리에서 7개 Delta 테이블 전체 해시·원본 버전 불변
- [x] 실제 합성 worker cgroup 메모리 peak·구간 CPU·executor queue 측정과 control 자원 조정
- [ ] 순수 pool 대기·더 큰 입력/동시 실행을 분리 측정해 운영 자원 설정 판단
- [ ] 유지보수 중인 Airflow/chart/provider 조합과 운영 metadata DB 검증

Databricks 성공은 합성 승하차 fixture, Kubernetes 성공은 단일 node 합성 lake를 대상으로 한다. 실수집·S3·실시간 관측·대규모 성능의 증거로 확대하지 않는다.

## Phase 6 — Free Edition의 관리형 처리와 SQL 제공

- [x] 새 전용 합성 schema에서 잘못된 최신 정정의 Silver 출판 차단과 기존 버전 보존
- [x] 정상 정정 후 목표 날짜만 변경·인접 날짜 보존·원본 재처리 해시 일치
- [x] Delta history/time travel로 이전 출판의 값·전체 해시 확인
- [x] Unity Catalog SQL view·COMMENT·품질 PASS 분석 제공 계약
- [x] 같은 합계의 역 identity 오류·누락 Gold 날짜가 SQL 분석에 출판되지 않는 실제 로컬 회귀
- [x] 기존 serverless SQL warehouse의 실제 네 쿼리와 notebook 결과 일치
- [ ] 실수집 입력·운영 기간·운영 부담/비용 비교를 통해 주 변환 경로 채택 여부 판단

운영 기술은 문제·대안·검증·도입 비용을 기준으로 선택한다. 실제 실행 성공과 도입 필요성을 구분한다. AWS 운영 후보와 Free Edition의 자동 통합은 아직 구현·검증하지 않았다.

## 저장소 공개 정리

- [x] 현재 실행 경로와 선택적 검증 CLI·플랫폼 증거의 탐색 안내
- [x] 미사용 코드·비활성 샘플·중복 Secret 생성/의존성 래퍼 제거
- [x] ETA 의미에 맞춘 알림 이름과 snapshot export의 공통 CLI 경로 정리
- [x] 실험 전체 행 해시의 공통화·버전 고정·기존 공개 증거와 호환 확인

현재 공개 증거와 역사적 실패 기록은 평가 근거로 보존한다. 위 정리는 미완료 장기 운영·S3·플랫폼 판단을 완료 처리하지 않는다.

## 표본 계획의 실행 감사

- [x] 고정 계획·날짜별 예약·캡처 결과 대조, 도래 슬롯 분모와 미확인 호출량 구분
- [ ] 실제 7일 관측 결과와 누락 원인 확인; 기록 없는 과거 관측은 복원하지 않는다

메타데이터 감사 기능의 완료와 실제 기간 관측의 완료를 구분한다. 운영 DAG의 5분 주기는 유지한다.

## 저장 원본의 처리 전 무결성

- [x] 수집 시 파일 체크섬 기록과 변환 시작 전 동일 bytes 검증
- [x] 기존 해시 없는 관측의 명시적 미검증 표시와 원본 보존
- [x] 행 수·수집 시각을 유지한 값 변경의 차단을 합성 오류 주입으로 확인

파일과 메타데이터를 함께 바꾸는 경우의 진본 인증은 이 체크섬 계약의 범위가 아니다. 실제 7일 수집·품질·원본 재처리 결과는 별도로 검증한다.
