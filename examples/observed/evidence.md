# 실제 서울 API 제한 관측

실제 원천을 호출한 날짜는 2026-10-11이다. 사용자 허용 후 기존 키로 도착 API 세 번과 승하차 API 한 번을 호출했다. 원본은 별도 ignored .work에 저장했다. 아래 값은 실제 생성한 [JSON](evidence.json)의 집계이며 합성 fixture가 아니다.

| 수집 시작(KST) | 2026-10-11T17:49:53.329397+09:00 |

모든 계획 슬롯이 수집됐어도 응답 상한과 미래 원천 시각을 품질 경고로 남겼다. 미래 시각은 원인을 확인하지 못했으므로 특정 서버의 시계 오류나 시간 보정을 단정하지 않는다. 실제 원천 13개 반복 자연키에서 서로 다른 recptnDt가 발견됐다. 같은 수집의 중복은 최신 원천 시각을 먼저 선택하도록 수정했고, 해시는 시각까지 같은 경우의 결정적 tie-breaker로 제한했다. ALL 조회로 전체 역·열차 커버리지를 확보했다고 주장하지 않는다. 원천 시각 나이는 API 생성 시각과 수집 시각의 차이이며 운행 지연·승객 대기시간이 아니다. 일간 도착 Gold는 이 세 snapshot의 요약이며 완전한 하루 운행 관측이 아니다. 미수집 D-1 데이터를 복원하거나 일간 보고서를 생성하지 않았다.

저장된 원본을 Bronze→Silver→Gold로 처리한 뒤 다시 변환했다. Delta 테이블 7개의 전체 행 SHA256과 행 수가 같고 두 Bronze 버전도 불변이다. Silver/Gold의 새 버전 커밋은 데이터 변경과 구분한다. 로컬 최초 처리·재처리·해시 비교는 64.225656초이며 대용량 성능·운영 SLA의 증거가 아니다.

원문 JSON·Bronze raw_payload·정제 행·API 키는 공개하지 않는다. 공개 파일은 실제 생성된 evidence.json과 byte가 같다. AWS 저장·Databricks 실행·Kubernetes 수집·장기 운영은 이 실험에서 수행하지 않았다. 재현과 API 예산·수집 범위 선택은 [절차](../../docs/SOURCE_OBSERVATION.md), 지속 수집 계획은 [로드맵](../../docs/ROADMAP.md)에 기록했다.

## 날짜별 수집 기록 비교의 첫 입력

[collection-summary.json](collection-summary.json)은 위 실제 capture 메타데이터를 새 비교 도구로 읽은 결과다. API나 Delta를 다시 읽지 않았으며, source_manifest_sha256은 공개 evidence.json의 capture 객체를 canonical JSON으로 해시한 값과 일치한다.

KST 20261011 한 날짜, 선언된 도착 슬롯 3개가 모두 collected이고 실패/일정 놓침은 0개다. 도착 GET 3회·승하차 GET 1회이며, 승하차 617행은 이용 날짜 20261007이다. 도착 응답은 각각 1,000행으로 상한에 세 번 도달했다. 이는 3,000개의 관측 행이며 고유 역 3,000개나 전체 네트워크 확보를 의미하지 않는다.

도착 요청·저장 시도 시간 표본은 3개, 중앙값 0.141184초·최대 0.183611초다. 분석 기준은 실제 비교 시점인 2026-10-11T22:26:44+09:00이며, 마지막 관측은 17:59:53.438266이다. 그 이후 수집을 계속하지 않았으므로 기준 시점의 관측 나이는 운영 파이프라인 실패나 원천 생성 지연으로 판정하지 않는다.

두 성공률의 값은 선언된 이 세 슬롯에서만 1.0이다. 하루 전체·여러 날 운영 성공률은 아직 측정하지 않았다. 장기 수집 기간과 호출량 승인 전에는 반복 API 수집을 시작하지 않는다. [실행 방법과 분모 계약](../../docs/SOURCE_OBSERVATION.md#여러-날짜의-수집-기록-비교)을 따른다.

## 수집 시점 체크섬의 범위

이 10/11 캡처는 schema 1로 수집됐다. source_file_sha256은 처리 시점에 읽은 파일의 해시이며 수집 당시의 체크섬 검증으로 확대하지 않는다. 원본과 기존 공개 JSON은 보존한다. 이후 schema 2의 수집 시점 체크섬과 변환 전 gate는 [무결성 계약](../../docs/SOURCE_OBSERVATION.md#저장-원본의-무결성-계약)과 [합성 손상 주입 증거](source-integrity.json)에 있다.

## 일간 보고서 연결

10/16에는 별도 승인된 승하차 GET 한 번으로 이용 날짜 10/8의 615행을 확보했다. 기존 10/11 도착 관측과 함께 10/12 기준 보고서를 로컬에서 생성했다. 원래 10/7 이용량만 있을 때는 날짜 누락으로 발행이 차단됐다. 보고서 기준일·이용 날짜·관측 날짜·실제 생성 시각은 [report-check.json](report-check.json)에 구분했다.

저장 원본 재처리에서 7개 테이블 내용·Bronze 버전, 보고서 본문·업무 context가 유지됐고 발행 해시 검증을 통과했다. 재처리로 바뀌는 Silver/Gold 버전까지 같은 context bytes라고 주장하지 않는다. 도착을 새로 호출하거나 과거 관측을 복원하지 않았다. 원문·보고서·context는 private .work에만 두고 집계와 해시만 공개한다.
